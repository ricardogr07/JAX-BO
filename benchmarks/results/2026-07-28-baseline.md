Baseline for the refactor, recorded on the current code (branch point
`8685b3a`, jaxbo 0.1.2) on the newest jax this code can run on. jax 0.9.2 is
that ceiling: `jnp.clip(..., a_min=...)` (23 call sites) emits a
DeprecationWarning there and is removed in jax 0.10, and `from pyDOE import
lhs` needs a module-name shim (installed distribution pydoe 1.3.0 exposes

Per-candidate EI cost: 62.8 ms / 256 = 0.245 ms per candidate, essentially
all Python-side jit dispatch. For scale, one batched `predict` over all 256
grid points takes 0.85 ms total.

Cold numbers are in-session (jax already initialized by earlier tests). A
fully fresh process pays more: the profiled cold `train` at n=128 took
1.95 s (see below).

### Run agreement

Three full runs. Runs 1 and 3 agree within noise: 3 to 11 percent on every
bench (train n=32: 33.70 vs 32.75 ms; train n=128: 101.01 vs 85.06 ms within
their own IQRs; predict: 0.85 vs 0.76 ms; EI loop: 62.77 vs 58.49 ms). Run 2
caught a background-load window on this desktop that inflated the
dispatch-bound benches (train n=32 +39 percent, EI loop +41 percent) while
the compute-bound train n=128/512 stayed within 2 to 8 percent. The baseline
column above is the median of the three runs, which discards that spike.
Treat deltas under ~15 percent on dispatch-bound benches, and under ~10
percent on train n=512, as noise on this machine.

## Profile: one cold GP.train call (n=128, num_restarts=3)

Artifacts: `2026-07-28-train-cprofile.prof` (binary, load with `pstats`) and
`2026-07-28-train-cprofile.txt` (top 40 by cumulative time). Fresh process,
total 1.95 s, 574,716 function calls. cProfile was used instead of
jax.profiler to avoid pulling the TensorBoard UI stack; the hotspots are
Python-level anyway.

Top hotspots:

1. **XLA compilation, 1.05 s (54 percent): 24 separate pjit compilations for
   one train call.** The jitted methods use `static_argnums=(0,)` with the
   model instance as the static arg and default object hashing, so the
   compile cache is keyed on instance identity: every new `GP(...)` object
   recompiles everything. Confirmed in-session, where bench_train's fresh
   instances still paid 0.44 to 2.30 s cold per size.
2. **scipy L-BFGS objective round trips, 0.77 s: 85 `objective()` calls (119
   scipy function evaluations).** Each optimizer step crosses the
   Python -> jitted `likelihood_value_and_grad` -> `onp.array` boundary,
   forcing a device sync per step; this is the entire warm-path cost of
   `train`.
3. **Sequential Python loop over `num_restarts`.** The 3 restarts run one
   after another through `minimize_lbfgs_grad`; they are independent and not
   vmapped or parallelized, so warm train time scales linearly with
   `num_restarts` (and the EI bench shows the same per-call dispatch pattern:
   0.245 ms per candidate through `gp.acquisition` in a Python loop).
