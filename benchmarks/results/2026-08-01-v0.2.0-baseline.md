# Baseline: v0.2.0, 2026-08-01 (Phase 3 comparison base)

Baseline for Phase 3, recorded on tag `v0.2.0` (commit `1b77a45`), the
released post-refactor package, on current jax. **This file replaces
`2026-07-28-baseline.md` as the comparison base for the 3a/3b/3c delta
tables** (issue #65): the old baseline predates the Phase 2 refactor and the
0.2.0 release, so deltas against it would conflate the refactor with the
optimization.

The refactor removed the old environment constraints: no jax pin (the
`jnp.clip(..., a_min=...)` call sites are gone) and no `pyDOE` shim (the
dependency was dropped). The suite runs unchanged, plus one bench added
since the old baseline: `ei_score_candidates` (the batched EI path, issue
#28, released in 0.2.0).

## Protocol: machine state checked before recording

Two runs recorded earlier the same night (02:41 and 02:45 local) were
**discarded as contaminated**: the machine was under background load. The
tells, kept here so future sessions recognize them:

- suite wall time about 4 minutes against about 30 seconds clean;
- medians 2 to 10x above the clean runs (EI consumer 430 and 1145 ms
  against 122 ms clean; warm train n=128 417 and 576 ms against 138 ms);
- run to run spread up to 166 percent on medians 4 minutes apart, with
  IQRs several times the clean ones.

Before the clean runs the machine was verified quiet: the load source (a
transient Ollama silent upgrade plus unidentified earlier activity) had
exited, about 16 GB RAM free, pagefile untouched, Docker/WSL idle, on AC.
**Rule: check for CPU burners and confirm suite wall time is about 30
seconds before trusting a recording session.**

Four clean runs were then recorded: runs 3, 4, 5 back to back, run 6 after
a 3 minute idle cooldown.

## Thermal state dominates cross-run variance

The back to back runs slow down monotonically (run 3 fastest of the three,
run 5 slowest), and the post-cooldown run 6 is the fastest run on every
bench with the tightest IQRs. This is turbo/thermal decay on a laptop
class CPU, not measurement error: on the two fast warm-train benches the
four runs' IQRs are **mutually disjoint**, four statistically distinct
machine states from idle-cold to worked-warm.

Consequences, encoded in how the numbers below are quoted:

- The old baseline's noise formula (drop runs whose IQR overlaps no other
  run) degenerates here: on warm train n=32 and n=128 it would drop
  everything, and elsewhere it would drop run 6, the best machine state,
  as the "outlier". Thermal state is a recurring real state, not an
  anomaly to filter.
- The **cross-session noise band is therefore the full spread** of the
  four clean run medians over the baseline. It is wide (27 to 86
  percent). An absolute number from a different session is comparable
  only to that precision.
- **Phase 3 deltas must come from paired runs in one session** (before and
  after builds interleaved, same thermal window), where the paired ratio
  is far more stable than the absolutes. A claimed improvement gates on
  the paired ratio clearing the per-bench IQR of that session's runs, not
  on beating this file's absolute medians.

These bands are what a cross-session absolute comparison must clear. For
paired same-session comparisons (the Phase 3 protocol) the relevant noise
is the per-run IQR above, an order of magnitude tighter on most benches.

## Derived numbers

- **The issue #30 gate, paired per run** (fresh minus warm at n=128, same
  thermal state): 538.1 / 370.8 / 329.1 / 259.7 ms for runs 3 to 6,
  median about **350 ms of instance-keyed recompilation per fresh
  `GP(...)`**; as a ratio, fresh costs 2.9 to 5.4x warm (median 3.7x).
  The effect the old baseline measured at 474 ms is alive in 0.2.0; 3a
  gates on the paired ratio.
- **Per-candidate EI**: consumer path 122.0 / 256 = **0.476 ms per
  candidate**; fused 71.5 / 256 = 0.279 ms (consumer costs 1.7x fused).
  `score_candidates` does all 256 in 1.61 ms, **0.006 ms per candidate,
  about 76x cheaper than the consumer loop**, confirming the issue #28
  result in the released package.
- **Against the 2026-07-28 medians** (direction only, code and env moved
  together): every bench's clean-run medians sit at or below the old
  baseline in the matching machine states; nothing regressed beyond
  noise. The refactor plus the jax 0.9 to 0.10 move did not cost the
  measured paths anything.
